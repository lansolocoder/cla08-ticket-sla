# 工单 SLA 与升级路由

用于本地服务工单 SLA 计时与升级路由的命令行项目。

需要 Python 3.12，无第三方依赖。在仓库根目录运行：

```bash
python3 -m sla_desk --help
python3 -m sla_desk --version
python3 -m unittest discover -s tests -v
```

## 工单数据

工单数据持久化在**当前工作目录**的 SQLite 文件 `sla-desk.db` 中，首次写入时自动创建；多次运行之间数据保持一致，失败的命令不会留下半条记录。

### 登记工单

```bash
python3 -m sla_desk register \
  --request-no CR-20260924-001 \
  --title "总部网络中断" \
  --email ops@example.com \
  --priority P1 \
  --submitted-at "2026-09-24T10:00:00+08:00"
```

校验通过后生成全局递增工单号 `T1`、`T2`……，状态为 `open`，提交时间文本按原样保存（支持 `+08:00` 偏移、`Z` 等 ISO 8601 形式），并输出工单号、状态和提交时间。登记成功即开始 SLA 响应计时。

- 同一客户请求号以**完全一致**的标题、邮箱、优先级、提交时间文本再次登记，视为重复请求的重试：不新建、不改写，输出原工单号，以 0 退出。
- 任一字段不同则报错并非零退出，不新建也不修改。
- 标题为空、邮箱不含 `@`、优先级不在 P1–P4、提交时间无法解析时，一次性列出全部无效字段并非零退出。

### SLA 响应计时

登记成功即开始计时，按优先级设定响应目标：

| 优先级 | 响应目标 |
| --- | --- |
| P1 | 15 分钟 |
| P2 | 30 分钟 |
| P3 | 4 小时 |
| P4 | 1 个工作日（等同 8 小时服务时段） |

服务时段为周一至周五 `09:00–18:00`。截止时间从提交时刻起按服务时段累计目标时长算出：落在服务时段外（夜晚、周末）的时间不计入，P1–P3 同样只在服务时段内消耗计时。提交时间文本自带时区偏移时按该偏移解释，无偏移按本地时间。

### 查看工单

```bash
python3 -m sla_desk show T1
```

输出客户请求号、标题、报障人、优先级、提交时间和状态，以及三行 SLA 计时信息：

```text
响应截止: 2026-09-24T10:15:00+08:00
已耗时: 5 分钟
剩余: 10 分钟
```

三行均按截止时间所在时区偏移（即提交时间的偏移）表示，分钟向下取整；剩余为负表示已超期。工单不存在或工单号格式非法时报错并非零退出。

### 暂停与恢复

```bash
python3 -m sla_desk pause  T1 "2026-09-24T10:05:00+08:00"
python3 -m sla_desk resume T1 "2026-09-24T10:10:00+08:00"
```

两个子命令各接受工单号与一个时刻参数（ISO 8601，可带偏移），时刻文本原样保存，成功后输出工单号、状态与暂停/恢复时间。

- 只有 `open` 工单可以暂停，只有 `paused` 工单可以恢复；重复暂停、恢复未暂停工单、对 `merged` 工单操作均报错并非零退出。
- 时刻无法解析、早于提交时刻，或早于上一次暂停/恢复时刻（乱序）均报错并非零退出，数据库不新增也不修改。
- 暂停期间不消耗计时；查看暂停中的工单时状态行输出 `paused`，剩余时长按暂停时刻冻结。
- 恢复后已耗时按服务时段累计，截止时间相应顺延：重新从已消耗时长起按服务时段累计目标时长。

### 合并工单

```bash
python3 -m sla_desk merge T2 T1   # 把 T2 并入主工单 T1
```

被并工单（T2）状态变为 `merged`，记录主工单号与合并时间，此后其客户请求号不能再用于新建工单；查看它时输出 `merged` 状态和主工单号，主工单原有字段保持不变。要求两单都存在、状态均为 `open` 且不是同一单；合并不可逆，已合并的工单不能再以主单或被并单身份参与合并。

### 列出工单

```bash
python3 -m sla_desk list
```

只显示 `open` 状态的工单，按工单号升序，每行输出工单号、优先级、标题和状态（制表符分隔）。
