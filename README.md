# 工单 SLA 与升级路由

用于本地服务工单 SLA 计时与升级路由的命令行项目。

需要 Python 3.12，无第三方依赖。在仓库根目录运行：

```bash
python3 -m sla_desk --help
python3 -m sla_desk --version
python3 -m unittest discover -s tests -v
```

## 工单数据

工单数据持久化在**当前工作目录**的 SQLite 文件 `sla-desk.db` 中，首次写入时自动创建；多次运行之间数据保持一致，失败的命令不会留下半条记录。

### 登记工单

```bash
python3 -m sla_desk register \
  --request-no CR-20260924-001 \
  --title "总部网络中断" \
  --email ops@example.com \
  --priority P1 \
  --submitted-at "2026-09-24T10:00:00+08:00"
```

校验通过后生成全局递增工单号 `T1`、`T2`……，状态为 `open`，提交时间文本按原样保存（支持 `+08:00` 偏移、`Z` 等 ISO 8601 形式），并输出工单号、状态和提交时间。

- 同一客户请求号以**完全一致**的标题、邮箱、优先级、提交时间文本再次登记，视为重复请求的重试：不新建、不改写，输出原工单号，以 0 退出。
- 任一字段不同则报错并非零退出，不新建也不修改。
- 标题为空、邮箱不含 `@`、优先级不在 P1–P4、提交时间无法解析时，一次性列出全部无效字段并非零退出。

### 查看工单

```bash
python3 -m sla_desk show T1
```

输出客户请求号、标题、报障人、优先级、提交时间和状态；工单不存在或工单号格式非法时报错并非零退出。

### 合并工单

```bash
python3 -m sla_desk merge T2 T1   # 把 T2 并入主工单 T1
```

被并工单（T2）状态变为 `merged`，记录主工单号与合并时间，此后其客户请求号不能再用于新建工单；查看它时输出 `merged` 状态和主工单号，主工单原有字段保持不变。要求两单都存在、状态均为 `open` 且不是同一单；合并不可逆，已合并的工单不能再以主单或被并单身份参与合并。

### 列出工单

```bash
python3 -m sla_desk list
```

只显示 `open` 状态的工单，按工单号升序，每行输出工单号、优先级、标题和状态（制表符分隔）。
